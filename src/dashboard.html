Context truth and safety layer

ctx makes your agent leaner without losing the thread.

Your coding agent drags around tool output it stops needing. ctx clears the dead weight from its context, but only the parts your own sessions prove are safe to drop. The tool still runs in full; ctx just shortens what the agent reads back.

Where each of your tools stands

Every tool climbs the same ladder, left to right. ctx leaves a tool's output whole until it reaches "trimming for real", and only then does it start cutting. Tap any stage for the tool-by-tool detail.

How ctx decides, in three rules
1
Cuts the bloat two ways
It filters MCP tools you rarely call before they reach the model, and shortens long tool output once a tool has earned it. Errors and the parts that matter are kept.
2
Proves before it trims for real
A tool only starts trimming for keeps after your own sessions show that trimming it did not make the agent re-read or correct more. Before that it watches, then tests quietly.
3
A trim is never a dead end
The tool still runs in full. ctx only shortens what the agent reads back, and if it needs the detail again it reads it again, which ctx counts and learns from.

When your agent compacts

When a coding agent runs low on room, it compacts: it summarizes and drops older detail so it can keep going. That is the platform's call, not ctx's. ctx just watches what happens next and counts the times a compaction was followed by you correcting the agent within a few turns. This is not proof the compaction caused the correction. It only tells you how often one came right after the other, on your own work, across the agents ctx can see.

Every agent, one honest layer

ctx sits under each coding agent you run and treats them as one. No agent vendor measures the others, so this is the one place you see Claude Code and Cursor side by side, on your own work. Each card is that agent's real activity. Where ctx hasn't seen an agent yet, it says so plainly instead of showing a zero.
